🛠️ 어떻게 해결했는가 (설계 전환) 편향 질문을 백지 비교 질문으로 교정하는 De-anchoring과 외부 패키지 0개 Pure Python AST 런타임 검증기(verify_asset.py)를 기초 골격으로 구축했습니다.

[1부 · Stage 1] 왜 일반·원터치 로컬 LLM은 실패하는가: 질문 탈앵커링과 순수 파이썬(Pure Python) AST 검증 골격

진화 단계: STAGE 1 (기초 검증 골격) · 원문 마크다운: 01-stage1-deterministic-python-verification-backbone.md
핵심 요약: 모델의 추론 능력이 올라갈수록 사용자의 잘못된 전제를 정교하게 합리화하는 '영리한 변호사 역설'이 발생하며, 서드파티 패키지에 의존한 코드는 버전 충돌로 쉽게 부패합니다. 이를 막기 위해 ① 질문 탈앵커링(Auto De-anchoring), ② 외부 패키지 0개 순수 파이썬(Pure Python Stdlib) 계산기, ③ AST 파싱 및 서브프로세스 실행(Exit Code 0) 검증 게이트(verify_asset.py)를 시스템의 첫 번째 주춧돌로 세웠습니다. 
import ast, subprocess, sys

ALLOWED_STDLIB = {
    "math", "dataclasses", "typing", "collections", "itertools",
    "functools", "statistics", "json", "re", "datetime", "enum",
    "hashlib", "sqlite3", "pathlib", "os", "sys", "vault_stdlib"
}

def audit_python_ast_and_runtime(code_str: str) -> bool:
    tree = ast.parse(code_str)
    for node in ast.walk(tree):
        if isinstance(node, ast.Import):
            for alias in node.names:
                if alias.name.split(".")[0] not in ALLOWED_STDLIB:
                    raise ValueError(f"External dependency blocked: {alias.name}")
    proc = subprocess.run([sys.executable, "-X", "utf8", "-c", code_str], capture_output=True, timeout=10)
    return proc.returncode == 0

def toggle_header_in_place(binary_path, keystream: bytes) -> None:
    with open(binary_path, "r+b") as fh:
        fh.seek(0)
        head = fh.read(len(keystream))
        fh.seek(0)
        fh.write(bytes(a ^ b for a, b in zip(head, keystream)))
        fh.flush()

발전 이유와 해법: 12GB VRAM 환경에서 별도 4B 드래프트 모델을 동시 상주시키면 VRAM 한계를 초과합니다. 이에 추가 VRAM을 0 Byte 쓰는 ① ReadableStream SSE 실시간 토큰 렌더링 & 즉시 중단 버튼(AbortController), ② 무모델 LLAMA_ARG_SPEC_TYPE=ngram-mod + FLASH_ATTN=on, ③ 공통 프리픽스 KV 캐시 재사용(CACHE_REUSE=256 & 슬롯 스냅샷)을 결합해 작업 관리자 노출 인자 0개를 유지한 채 첫 글자 대기 시간을 8.83초 → 0.037초(240.1배 단축)로 줄였습니다. 
# Zero-Argv 가속 환경변수 (작업 관리자 노출 CLI 플래그 0개 유지)

[9부 · Stage 9] 외부 벡터 DB 없이 45.8만 건 의미 검색 완성하기: GPU VRAM을 0바이트 쓰는 CPU `BGE-M3` 사이드카와 `SQLite FTS5`의 2단계 가중 RRF 결합

진화 단계: STAGE 9 (Zero-VRAM 시맨틱 리랭커 & Int8 코어 캐시) · 원문 마크다운: 09-stage9-cpu-bgem3-hybrid-rrf-zero-vram-reranker.md
발전 이유와 해법: 전문 용어가 전혀 없는 순수 비유·개념 질문(예: "비밀은 안 알려주고 정답을 안다는 사실만 증명" → 영지식 증명)을 외부 벡터 DB 없이 해결하기 위해, SLOT_0(bge-m3-q8_0.gguf)를 순수 CPU(LLAMA_ARG_DEVICE=none, 추가 GPU VRAM 0 MiB) 사이드카(:8082)로 구동했습니다. 평문을 저장하지 않는 Int8 양자화 코어 캐시(1 KB/문서, 코사인 충실도 >0.9995)와 레짐 분리형 가중 RRF(k=60)로 어휘 0% 일치 문서를 구제하면서도 기존 법령 조문 정확도를 100% 보존했습니다. 
# 어휘 신뢰도(lex_sc)와 BGE-M3 코사인(cos_val) 레짐에 따라 가중치를 분리하는 2-Stage RRF (k=60)
w_lex = 1.38 if lex_sc >= 28.0 else 0.65
w_sem = 1.18 if cos_val >= 0.50 else (1.02 if cos_val >= 0.43 else 0.0)
rrf_score = (w_lex / (60.0 + r_lex)) + (w_sem / (60.0 + r_sem)) + min(0.0040, lex_sc / 25000.0)

발전 이유와 실제 포착 사례: 복합 사건 질문에서 최대 3개의 직교 도메인 계산기를 단일 패스로 연쇄 실행(/api/l3-run-batch, 파이썬 배치 5.94ms)하도록 확장했습니다. 특히 라이브 테스트 중 로컬 LLM이 9억 원(900,000,000)을 쉼표로 표기하다가 0 하나를 빠뜨리는 한국어 억↔쉼표 10배 자릿수 누락(90,000,000원) 현상을 발견하여, 인용 범위·원문 조문·수치 보존·ZERO_DIGIT_SHIFT_10X를 전수 검문하고 위반 시 1회 자동 재작성하는 사후 역검증기를 완성했습니다. 
# 사후 생성 답변 결정론적 4중 검문: (1) #k 인용 경계, (2) 원문 조문, (3) 반올림 왜곡, (4) 한국어 억<->쉼표 10배 자릿수 누락
is_zero_shift = abs(ans_val * 10.0 - auth_val) <= 1.0 or abs(ans_val / 10.0 - auth_val) <= 1.0
if is_zero_shift:
    violations.append(f"ZERO_DIGIT_SHIFT_10X: '{raw_surface}' != {auth_val:,.0f}")
